# TinyGPT: Character-Level Decoder-Only Transformer Analysis

본 저장소는 셰익스피어 대본(`tinyshakespeare`)을 학습하여 텍스트를 생성하는 문자 단위(Character-Level) 언어 모델의 동작 원리를 밑바닥부터 해체하고 분석한 학습 프로젝트입니다. 

Andrej Karpathy의 교육용 모델과 OpenAI의 GPT 시리즈에 쓰인 핵심 구조(Decoder-Only Transformer)를 바탕으로 작성되었습니다. 단순히 완성된 코드를 실행해 보는 것에 그치지 않고, **데이터가 모델에 입력되어 결과를 내기까지의 모든 과정에서 텐서(Tensor)의 형태(Shape)가 어떻게 변하는지, 그리고 그 계산들이 어떤 수학적 의미를 가지는지를 코드를 하나하나 뜯어보며 완벽하게 이해하는 것**에 분석의 중점을 두었습니다.

---

## 1. 하이퍼파라미터 및 모델 규격 (Model Configuration)

본격적인 텐서 흐름 분석에 앞서, 모델 내부에서 발생하는 모든 행렬곱 연산의 기준 규격이 되는 하이퍼파라미터를 정리했습니다.

| 변수명 | 설정값 | 모델 내부에서의 역할 |
| :--- | :--- | :--- |
| `vocab_size` | 65 | 텍스트 내 고유 문자(알파벳, 특수기호) 총개수로, 최종 출력층의 분류 차원 크기 |
| `block_size` | 64 | 모델이 한 번에 참고할 수 있는 문맥의 길이(Sequence Length)이자 시간 축($T$) |
| `emb_dim` | 128 | 글자 1개가 변환되는 특징 벡터의 차원 크기(Channel, $C$) |
| `num_heads` | 4 | Multi-Head Attention 연산 시 128차원을 쪼개어 분석하는 병렬 부서의 개수 |
| `num_layers` | 4 | 어텐션과 피드포워드 계층이 중첩된 트랜스포머 블록의 적층 횟수 |

## 2. 텐서 차원 변화 및 데이터 흐름 추적 (Data Flow Mechanics)

본 모델을 분석하며 가장 집중적으로 탐구한 부분입니다. 입력 데이터가 모델의 4개 층을 통과하며 어떻게 공간을 팽창시키고 의미를 압축하는지, 배치 크기(`B=64`)와 시퀀스 길이(`T=64`)를 기준으로 단계별로 추적했습니다.

### Step 1. 입력층 (`[64, 64]`)
최초의 데이터는 문자가 아닌 정수 인덱스(0~64)로 구성된 2차원 텐서로 입력됩니다. 
`[64(배치), 64(시점)]`의 형태이며, 이는 64개의 문장(배치) 안에 각각 64개의 글자 인덱스가 시간 순서대로 나열되어 있음을 의미합니다.

### Step 2. 임베딩과 공간의 팽창 (`[64, 64, 128]`)
정수 텐서가 임베딩 레이어를 통과하면 `[B, T, C]` 형태의 3차원 연속 실수 공간으로 팽창합니다. 
이 과정에서 두 가지 임베딩이 덧셈 연산으로 융합되는 것을 확인했습니다.
1. **Token Embedding:** 정수 인덱스 1개가 128차원의 특징 벡터로 변환됩니다.
2. **Positional Embedding:** 트랜스포머는 자체적으로 시퀀스의 순서를 인지하지 못하므로, 각 시점(위치) 고유의 128차원 좌표 벡터를 생성하여 기존 토큰 벡터에 더해줍니다. 이를 통해 각 데이터는 시공간적 위치 정보를 획득합니다.

### Step 3. 트랜스포머 블록 내부 통과 (`[64, 64, 128]`)
데이터는 4층의 트랜스포머 블록을 통과합니다. 층을 오가는 동안 텐서의 외형은 `[64, 64, 128]`로 일정하게 보존됩니다. 이는 가중치 행렬의 규격을 맞추고 깊은 신경망의 학습 안정성을 유지하기 위함입니다. 외형은 유지되지만 내부 데이터는 다음 두 연산을 통해 고도로 정제됩니다.

* **Multi-Head Attention (문맥의 융합):** 128차원의 벡터를 통째로 연산하지 않고 4개의 Head(각 32차원)로 쪼개어, 각기 다른 관점에서 쿼리(Q)와 키(K)를 내적하여 연관도 점수를 계산합니다. 이때 텍스트 생성 모델의 특성상 미래의 글자를 커닝하지 못하도록, 대각선 우측 상단을 `-inf`로 차단하는 **인과적 마스킹(Causal Masking)**이 적용되어 있습니다. 쪼개서 분석된 결과는 다시 합쳐진 뒤 `Linear(128, 128)` 레이어를 거치며 유기적으로 혼합됩니다.
* **Position-wise FeedForward (독립적 비선형 압축):**
  어텐션이 시점($T$) 간의 교류라면, FFWD는 각 위치에서 독립적으로 수행되는 연산입니다. 128차원의 정보를 4배(512)로 부풀려 `ReLU`로 비선형 특징을 추출하고, 다시 128차원으로 압축하는 구조를 통해 모델의 표현력을 극대화한 것을 확인할 수 있습니다.

(※ 층을 통과할 때마다 원본 값을 더해주는 Residual Connection과 분산을 정규화하는 LayerNorm이 적용되어 기울기 소실을 방지합니다.)

### Step 4. 출력층 (`[64, 64, 65]`)
마지막 LM Head는 파이토치 `Linear` 레이어의 브로드캐스팅 특성을 활용합니다. 앞의 두 차원(`[64, 64]`)은 훼손하지 않고 마지막 128차원 벡터만 타겟으로 행렬곱을 수행합니다. 그 결과 128차원의 문맥 정보가 최종 예측 타겟인 65개의 알파벳 후보군 확률 점수(Logits)로 변환됩니다.

## 3. 학습 및 추론 제어 루프 분석 (System Operations)

모델 구조뿐만 아니라, 파이토치 시스템 상에서 데이터를 채점하고 새로운 문장을 만들어내는 과정 또한 세밀하게 분석했습니다.

### 학습 시 파이토치 채점 규격 매칭 (Transpose)
모델은 한 번에 64개의 시점에서 '그다음 올 글자'를 동시에 예측하므로 출력 텐서는 `[64(B), 64(T), 65(C)]`의 모양을 갖습니다. 
그러나 파이토치의 `F.cross_entropy` 함수는 내부 계산의 효율을 위해 분류 기준이 되는 차원이 반드시 두 번째 자리(`[B, C, T]`)에 오도록 강제합니다. 따라서 수학적 계산의 이유가 아니라 단순히 시스템의 규격을 맞추기 위해 `logits.transpose(1, 2)`를 호출하여 축을 비틀어준 뒤 병렬로 오차(Loss)를 계산하는 구조를 파악했습니다.

### 자가회귀 생성의 꼬리 물기 (Autoregressive Sampling)
학습된 모델로 새로운 텍스트를 만들어낼 때는 다음과 같은 흐름을 따릅니다.
1. **예측 타겟 슬라이싱 (`logits[:, -1, :]`):** 주어진 과거 문맥을 다시 예측하는 것은 불필요하므로, 모델이 반환한 전체 길이($T$) 예측 값 중 가장 마지막 글자 다음에 올 점수만 잘라서 가져옵니다.
2. **다양성 확보 (`multinomial`):** 항상 가장 높은 점수의 글자만 고르면 똑같은 말만 반복하게 되므로, `Softmax` 확률 분포를 기반으로 주사위를 굴려 토큰을 뽑는 `torch.multinomial` 샘플링 방식이 사용되었습니다.
3. **Sliding Window:** 생성된 새 글자를 문맥 맨 뒤에 붙이고, 한계치(`block_size=64`)를 넘어가면 가장 오래된 앞 글자를 버리면서 텍스트 생성을 무한히 지속합니다.

## 4. 실행 방법 (Quick Start)

```python
import torch
from notebook_06 import TinyGPT, sample_gpt

# 하드웨어 장치 가속 세팅
device = "cuda" if torch.cuda.is_available() else "cpu"

# 모델 객체 초기화
model = TinyGPT(vocab_size=65, block_size=64, emb_dim=128, num_heads=4, num_layers=4)
model.to(device)

# 사전 학습된 모델 가중치 및 단어 맵핑 사전(stoi, itos) 로드 후 텍스트 생성
generated_text = sample_gpt(
    model, 
    block_size=64, 
    stoi=stoi, 
    itos=itos, 
    device=device, 
    start_text="ROMEO:", 
    max_new_tokens=400
)

print(generated_text)
