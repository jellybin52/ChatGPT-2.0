# TinyGPT: Character-Level Decoder-Only Transformer 분석 보고서

본 저장소는 셰익스피어 대본(`tinyshakespeare`)을 학습하여 텍스트를 생성하는 문자 단위 언어 모델의 동작 원리를 밑바닥부터 해체하고 분석한 학습 프로젝트입니다. 

Andrej Karpathy의 교육용 코드와 OpenAI의 GPT 시리즈에 쓰인 핵심 구조(Decoder-Only Transformer)를 모델로 삼았습니다. 완성된 코드를 무작정 실행하기보다, 데이터가 모델을 거쳐 결과를 내기까지의 과정에서 텐서(Tensor)의 형태(Shape)가 어떻게 변하는지, 그리고 각 계산식이 가지는 수학적 의미를 한 줄씩 뜯어보며 파악하는 것에 분석의 중점을 두었습니다.

---

## 1. 하이퍼파라미터 및 모델 규격 (Model Configuration)

본격적인 텐서 흐름 분석에 앞서, 모델 내부에서 발생하는 모든 행렬 계산의 기준 규격이 되는 하이퍼파라미터를 정리했습니다.

| 변수명 | 설정값 | 모델 내부에서의 역할 |
| :--- | :--- | :--- |
| `vocab_size` | 65 | 텍스트 내 고유 문자(알파벳, 특수기호) 총개수로, 최종 출력층의 분류 차원 크기가 됩니다. |
| `block_size` | 64 | 모델이 한 번에 참고할 수 있는 문맥의 최대 길이(Sequence Length)이자 시간 축($T$)입니다. |
| `emb_dim` | 128 | 글자 1개가 변환되는 특징 벡터의 차원 크기(Channel, $C$)입니다. |
| `num_heads` | 4 | Multi-Head Attention 연산 시 128차원을 쪼개어 분석하는 병렬 부서의 개수입니다. |
| `num_layers` | 4 | 어텐션과 피드포워드 계층이 중첩된 트랜스포머 블록의 적층 횟수입니다. |

---

## 2. 전처리와 학습 데이터 구성 (Dataset & Tokenization)

컴퓨터는 문자 자체를 연산할 수 없으므로, 학습 시작 전 데이터를 숫자로 바꾸고 문제지(`xb`)와 정답지(`yb`)로 나누는 과정을 분석했습니다.

### 문자와 정수의 상호 매핑 (stoi & itos)
코드의 가장 기저에는 `stoi`(String to Integer)와 `itos`(Integer to String)라는 두 가지 사전(Dictionary)이 정의되어 있습니다. `stoi`를 통해 대본 전체가 정수 인덱스 리스트로 변환되어 모델에 입력되고, 학습이 끝난 후 모델이 뱉어낸 숫자 정답은 `itos`를 통해 다시 사람이 읽을 수 있는 문자로 복원됩니다.

### 문제지 `xb`와 정답지 `yb`의 병렬 구조
학습을 위해 배치 크기 64 단위로 데이터를 묶어 가져옵니다.
* **문제지 `xb` (`[64, 64]`):** 64개의 문장 묶음 안에 각각 64개의 글자 인덱스가 순서대로 들어있는 2차원 텐서입니다.
* **정답지 `yb` (`[64, 64]`):** 정답지 역시 `xb`와 완전히 동일한 크기의 2차원 텐서입니다. 구조를 확인해보니 `xb` 문맥에서 정확히 한 칸씩 오른쪽으로 밀려있는 '다음 글자들'이 담겨 있었습니다. 모델이 시퀀스의 맨 마지막 글자 하나만 맞추는 게 아니라, 64개의 위치 각각에서 "내 다음에 올 글자는 무엇인가?"를 동시에 병렬로 학습하도록 데이터가 설계되어 있음을 파악했습니다.

## 3. 핵심 분석: 텐서 차원 변화 및 데이터 흐름 추적 (Data Flow Mechanics)

입력 텐서 `xb`가 모델의 각 계층을 통과하며 어떻게 차원을 확장하고 수축하는지 단계를 쫓아가며 정리했습니다.

### Step 1. 임베딩을 통한 차원 확장 (`[64, 64, 128]`)
`[64, 64]` 모양의 정수 데이터가 임베딩 레이어를 통과하면 `[B, T, C]` 형태의 3차원 연속 실수 공간으로 늘어납니다. 정수 번호표 하나가 128차원의 특징 벡터로 대체되는 과정입니다. 
여기에 글자 자체의 의미를 담은 `Token Embedding`과, 글자의 앞뒤 순서 좌표를 담은 `Positional Embedding`이 덧셈 연산으로 합쳐집니다. 트랜스포머는 모든 글자를 동시에 계산하므로 순서를 모르는 특성이 있는데, 이 결합을 통해 각 시점의 데이터가 문장 내에서의 위치 정보를 획득하게 됩니다.

### Step 2. 트랜스포머 블록 내부 연산 (`[64, 64, 128]`)
데이터는 총 4층으로 이루어진 블록 내부를 관통합니다. 층을 오가는 동안 가중치 행렬과의 규격을 맞추고 학습 안정성을 유지하기 위해 텐서의 외형적 차원은 `[64, 64, 128]`로 일정하게 보존됩니다. 외형은 같지만 내부에서는 다음 두 가지 연산이 일어납니다.

* **Multi-Head Attention 연산과 Q, K, V의 행렬곱 논리:**
  128차원의 벡터를 통째로 연산하지 않고 4개의 Head로 쪼개어 각각 32차원(`head_size = 128 // 4`)씩 들고 연산을 수행합니다. 각 Head 안에서 글자 벡터는 세 개의 독립적인 가중치 행렬(Linear 레이어)을 거치며 Query, Key, Value라는 세 가지 성격의 벡터로 변환됩니다. 
  Query는 현재 시점의 글자가 과거 글자들에게 정보를 요청하기 위해 던지는 '질문'의 역할을 하고, Key는 다른 글자들의 질문을 받아들이기 위해 나열해 둔 '이름표'의 역할을 수행합니다. Value는 실제 그 글자가 들고 있는 '구체적인 정보 내용'입니다. 
  코드에서 가장 집중해서 분석한 부분은 `q @ k.transpose(-2, -1)` 계산이었습니다. 질문 행렬(`q`, `[64, 64, 32]`)과 누워있는 이름표 행렬(`k.transpose`, `[64, 32, 64]`)이 곱해지면서, 맞닿아 있는 특징 차원(32)이 내적 연산을 통해 완전히 사라집니다. 결과적으로 특징 차원은 증발하고 시간 축만 남은 `[64, 64, 64]` 크기의 연관성 점수판이 만들어집니다. 이 표는 각 글자가 과거의 어떤 글자와 문맥적으로 긴밀한지를 보여주는 지도가 됩니다. 여기에 미래 글자를 가려주는 인과적 마스킹(Causal Masking)을 거쳐 소프트맥스 확률을 구한 뒤, 진짜 정보인 `v` 행렬과 곱해주면 과거 문맥이 유기적으로 흡수된 똑똑한 벡터가 완성됩니다. 쪼개졌던 결과들은 나중에 가로로 합쳐져 원래의 128차원으로 돌아옵니다.

* **Position-wise FeedForward의 독립 비선형 압축:**
  어텐션이 시점 간의 교류였다면, 피드포워드는 각 위치에서 독립적으로 수행되는 연산입니다. 시간 축($T=64$)을 서로 침범하는 계산 없이, 오직 각 시점의 128차원 정보만 타겟 삼아 4배(512차원)로 부풀린 뒤 `ReLU`로 비선형 특징을 추출하고, 다시 원래 크기인 128차원으로 핵심 요약본을 압축합니다. 이 과정을 거치며 모델의 추론 표현력이 고도화됩니다.

(※ 블록을 거칠 때마다 원본 값을 연산 결과에 그대로 더해주는 Residual Connection과, 숫자가 폭주하는 것을 막기 위해 분산을 정규화하는 LayerNorm이 신경망 전반의 안정성을 잡아주는 구조도 확인했습니다.)

### Step 3. 최종 출력층 (`[64, 64, 65]`)
블록을 통과한 `[64, 64, 128]` 텐서는 마지막으로 LM Head(Linear Layer)를 만납니다. 파이토치 Linear 계층의 특성에 따라 앞 차원(`[64, 64]`)은 유지된 채 128차원의 벡터만 65개의 알파벳 후보군 차원으로 투영됩니다. 그 결과 최종 예측 `logits`는 `[64, 64, 65]` 형태의 점수판으로 출력됩니다.

## 4. 학습 및 문장 생성 제어 시스템 분석 (System Operations)

### 파이토치 채점 규격 매칭을 위한 Transpose 트릭
모델이 내놓은 최종 예측 `logits`는 `[64(B), 64(T), 65(C)]` 모양입니다. 이 예측을 정답지 `yb`(`[64, 64]`)와 비교해 오차를 구해야 하는데, 파이토치의 `F.cross_entropy` 함수는 내부 계산 효율화를 위해 분류 기준 차원이 반드시 두 번째 자리(`[B, C, T]`)에 오도록 설계되어 있습니다. 
따라서 수학적 모델링 이유가 아니라 순전히 프레임워크 규격을 맞추기 위해 `logits.transpose(1, 2)`를 호출하여 축을 `[64, 65, 64]`로 비틀어준 뒤 병렬로 손실(Loss)을 계산하고 가중치를 업데이트하는 시스템 구조를 파악했습니다.

### 자가회귀 생성의 꼬리 물기 구조 (Autoregressive Sampling)
학습이 끝난 모델로 문장을 새로 생성할 때는 다음과 같은 자가회귀 추론 논리가 적용됩니다.
1. **마지막 위치 슬라이싱:** 문맥을 넣으면 모델은 전체 입력 길이에 대한 예측을 반환하지만 과거 위치의 결과물은 관심 대상이 아닙니다. 오직 맨 마지막 글자 바로 다음에 올 정답만 원하므로, 시간 축의 맨 마지막 인덱스만 잘라오는 `logits[:, -1, :]` 슬라이싱 연산을 적용합니다.
2. **다양성 확보 (`multinomial`):** 항상 가장 높은 점수의 글자만 고르는 방식을 취하면 똑같은 문장만 반복해서 뱉어내는 오류 루프에 갇힙니다. 이를 피하기 위해 추출한 점수들을 `Softmax` 확률 분포로 바꾸고, 이 확률의 무게감에 따라 주사위를 굴려 토큰을 뽑는 `torch.multinomial` 방식을 사용해 다채로운 문장 생성을 유도합니다.
3. **Sliding Window:** 선택된 새 글자를 기존 문맥 맨 뒤에 결합(`torch.cat`)시키고, 문맥이 최대 한계선인 64자를 넘어가면 가장 오래된 맨 앞 글자를 버리면서 새로운 글쓰기를 끊임없이 이어 나가는 흐름을 분석했습니다.
